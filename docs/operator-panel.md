# Панель TASK

Панель создаёт TASK загрузкой одного CIDR-файла и показывает четыре этапа:
развёрнутые IP, Masscan, HTTPX и подтверждённые fingerprint-результаты.

Главный список в деталях TASK показывает только подтверждённые `ip(2)`:
`protocol://IP:PORT` с ответом HTTPX и совпавшим fingerprint. Список разбит на
страницы по 200 строк; экспорт TXT содержит все подтверждённые адреса без
промежуточных `ip(1)`. Если совпадений нет, панель явно показывает пустой
результат и не скачивает пустой файл. Таблицы исходных IP и открытых портов
доступны только в сворачиваемой диагностике. Обновление запрашивает реальный
статус API; результат не считается завершённым по факту постановки в очередь.

При создании TASK кнопка блокируется до ответа API, затем новая задача сразу
появляется в списке и открывается её прогресс. Ошибка API сохраняет заполненную
форму для исправления. Путь HTTPX, схемы и маркеры передаются вместе с выбранным
fingerprint; например, PAN-OS использует `/php/login.php` и `https`.

Для больших CIDR-файлов worker сначала записывает IP в TASK-базу. До окончания
этого этапа Masscan не запускается. Панель показывает «подготовка IP» и число
записанных адресов относительно объёма CIDR, а ожидающие задачи — «в очереди».
Ошибка любого Masscan/HTTPX-чанка завершает TASK со статусом «ошибка»; причина
доступна в деталях и событиях worker. Статус «завершён» означает, что все
созданные чанки отработали успешно.

В форме TASK кнопки «Параметры Masscan» и «Параметры HTTPX» открывают отдельные
модальные окна. Каждое поле имеет описание и обновляет итоговую argv-команду.
HTTPX в этом окне — ProjectDiscovery HTTPX из task-runner; одноимённый Python-клиент
на хостовой Kali к сканеру отношения не имеет. Редкие аргументы доступны в поле
«Прочие аргументы» и передаются как безопасный массив argv без shell.

В рабочем пространстве TASK блок «Детализация конвейера» показывает шаг 0
`ip(0)` (CIDR, IP и чанки), шаг 1 `ip(1)` (открытые порты и Masscan-чанки),
проверку HTTPX и отдельный результат `ip(2)` после fingerprint. Сам факт
HTTPX-ответа ещё не означает `ip(2)`. Для этапов видны состояния `ожидает`,
`работает`, `готово` и `ошибка`; данные обновляются примерно раз в секунду.

Под списком результатов есть два независимых окна логов: Masscan показывает
потоковые строки скорости, прогресса, найденных портов и события чанков;
HTTPX показывает начало и завершение чанков, число входных адресов, ответов,
совпадений и ошибки. События читаются из отдельной базы TASK, а при открытии
панели сначала загружаются последние 400 записей, затем новые. HTTPX запущен
с `-silent`, поэтому отдельный запрос без ответа не создаёт строку лога;
число проверенных адресов видно в статистике чанков.

В блоке «Сохранённые шаблоны поиска» кнопка «Новый» очищает выбор и переводит
форму в режим создания. Кнопка «Создать шаблон» сохраняет текущие параметры в
контрольной базе. После выбора шаблона становятся доступны «Загрузить»,
«Сохранить изменения» и «Удалить»; удаление требует подтверждения. Кнопка
«Проверить конфигурацию» открывает сухой тест argv и ограниченный реальный тест
на выбранном CIDR-файле. Если шаблоны не загружаются, сначала проверьте health
API и применённую миграцию контрольной базы.

Операции и API описаны в [task-operations.md](task-operations.md).
